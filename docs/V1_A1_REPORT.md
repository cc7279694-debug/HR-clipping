## 2. 真实宿主方法与边界

本轮使用**本机已安装 Codex 的原生 app-server/stdio 宿主**，不是 Codex 子代理模拟，也不是将 SKILL.md 内容复制到提示词。先读取本机帮助及由原生程序生成的协议 schema，再按其支持的字段请求：

1. `initialize` / `initialized`。
2. `skills/list`，分别指定仓库根目录和父工作区，`forceReload: true`。
3. `thread/start`，仓库根目录、新会话、只读、禁止提权询问；模型和其他配置沿用现有设置，不修改全局配置。
4. 正式探针：`turn/start.input` 包含原生 `type: "skill"`、名称 `hr-clipping`、**从目录结果获得的路径**，以及包含 `$hr-clipping` 的本期请求。客户端未拼接 Skill 正文。
5. 负向探针：另一个新会话，仅发送普通 React 调试文字，不含 skill 输入。
6. 等待 `turn/completed`，核对仅这两个本次新会话的原生记录；关闭本轮临时 app-server 子进程。

这验证了原生目录发现和正式 Skill 输入/加载通道。**没有操作桌面 GUI 的 `$` 候选菜单、截图或手工键入界面，因此这些 UI 层结果仍 NOT_RUN。** 元数据中的客户端来源标签不作为桌面或 VS Code UI 实测的证据。

另补测“仅发送含 `$hr-clipping` 的文字，不附结构化选择项”。新 app-server 在初始化响应前报本机状态 SQLite 初始化失败；随后仅一次改用既有服务 proxy 的有界重试，又在连接本地控制 socket 时返回 os error 10050。**该补充项为 BLOCKED，没有创建模型回合，不能写成纯文字调用通过或 Skill 解析失败。** 未手工修改/修复全局数据库、权限、网络、插件或软件；正常新会话记录由原生宿主保存，不继续扩大排障范围。

桌面已保存的 SKILLS 项目指向仓库父目录；现有新建任务工具不能直接覆盖到子目录。实际测试使用精确仓库 cwd 的原生新会话，不能把父目录和仓库根目录混为一谈。
